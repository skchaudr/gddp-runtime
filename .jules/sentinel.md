## 2025-02-28 - Missing Error Handling Exposing Stack Traces in Webhook Intake
**Vulnerability:** The Flask `/webhook` endpoint in `scripts/intake_server.py` lacked `try...except` blocks for `json.JSONDecodeError` and `sqlite3.Error`. When receiving malformed JSON payloads or encountering database failures during insertion, the server would crash and potentially leak internal stack traces (including database internals) in the HTTP 500 responses to the client.
**Learning:** In Flask webhook endpoints, operations that can raise exceptions based on uncontrolled external input (like `json.loads`) or internal state (like `con.execute`) must be explicitly caught and handled to prevent information disclosure.
**Prevention:** Always wrap external payload processing (`json.loads`) and database interactions in `try...except` blocks inside API endpoints. Catch specific exceptions, log the actual error securely on the server side, and return generic, safe HTTP response messages (e.g., 400 Bad Request or 500 Internal Server Error) to the caller.
