## 2024-05-25 - Fail Closed on Missing Authentication Secrets
**Vulnerability:** Webhook authentication bypass due to `verify_signature` returning `True` and `/webhook` bypassing signature validation entirely if `WEBHOOK_SECRET` was empty.
**Learning:** Returning `True` (failing open) when an authentication secret is missing entirely defeats the purpose of the security check and allows unauthenticated attackers to forge arbitrary requests if the application is misconfigured. In addition, internal server errors (like `json.JSONDecodeError` or `sqlite3.Error`) were unhandled, potentially leaking stack traces or database internal state to the end user.
**Prevention:** Always fail closed: if an authentication secret is missing, validation must explicitly fail (e.g., return `False` or throw a configuration error). Ensure the authentication checks are mandated at the entry point without bypass conditions. Wrap untrusted input deserialization and sensitive backend operations (like database interactions) in `try...except` blocks to return generic, safe HTTP error responses (e.g., 400 Bad Request, 500 Internal Server Error) instead of unhandled exceptions.
