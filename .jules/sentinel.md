## 2026-05-28 - [Webhook Authentication Bypass & Info Leak]
**Vulnerability:** The `/webhook` route bypassed signature verification (`if WEBHOOK_SECRET and ...`) and returned `True` by default if no secret was configured, leaving the intake server completely unauthenticated. Additionally, invalid JSON payloads and DB errors leaked stack traces or raised internal errors to callers.
**Learning:** Hardcoding default open access when a secret is missing creates an unauthenticated backend bypass that an attacker can exploit just by sending arbitrary POST requests to the intake endpoint. Also, failing to wrap data parsing/DB logic exposes the internal workings of the server.
**Prevention:** Webhook endpoints must always mandate authentication (fail-closed, `return False`). Input data (JSON payloads) and database operations must be wrapped in specific try/except blocks (`json.JSONDecodeError`, `sqlite3.Error`) that return generic secure HTTP 400/500 errors to clients, preventing information leakage.
