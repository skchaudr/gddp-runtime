## 2024-05-15 - Fail Securely and Prevent Stack Trace Leakage
**Vulnerability:** The Flask webhook application (`intake_server.py`) lacked exception handling for `json.JSONDecodeError` during payload parsing and `sqlite3.Error` during database interaction. If an invalid JSON was sent or the database failed (e.g. schema error or missing DB), the application would throw an unhandled exception, which could expose internal stack traces and server state to the caller.
**Learning:** In Flask/Python APIs, unhandled exceptions can leak sensitive internal details (stack traces, variables, structure) back in HTTP responses or visible server logs. Failing securely requires explicit try/except boundaries that catch specific known exceptions and map them to generalized HTTP error codes (like 400 Bad Request or 500 Internal Server Error) with safe, opaque error messages.
**Prevention:** Always wrap external input parsing (like `json.loads`) and stateful persistence operations (like `sqlite3.connect/execute`) in explicit exception handlers. Return uniform, non-descriptive error responses (e.g. `{"error": "invalid json"}`) rather than raw exception strings.
