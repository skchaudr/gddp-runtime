## 2026-06-14 - Fix Authentication Bypass and Prevent Information Leakage in Webhook Server
**Vulnerability:** The `/webhook` endpoint in `scripts/intake_server.py` had a fail-open authentication check, completely bypassing payload verification if the `WEBHOOK_SECRET` environment variable was omitted. Additionally, unhandled `json.JSONDecodeError` and `sqlite3.Error` exceptions in the same file could expose internal system stack traces in the HTTP response.
**Learning:** Hardcoded conditional checks on security secrets (`if not WEBHOOK_SECRET: return True`) can easily lead to full authentication bypasses in production if configuration fails or is forgotten. Relying on default framework exception handling for databases and parsing exposes dangerous structural insights to attackers.
**Prevention:** Always default to "fail closed" (returning `False` or an error) for missing security configuration. Wrap all sensitive external-facing interactions (JSON parsing, DB writes) in `try-except` blocks and return standardized HTTP error codes (e.g., 400, 500) without leaking stack traces.
