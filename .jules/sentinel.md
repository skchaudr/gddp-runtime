## 2026-06-13 - [Missing Error Handling Leads to Stack Trace Leakage in Webhook Server]
**Vulnerability:** The `/webhook` endpoint in `scripts/intake_server.py` parsed incoming JSON and inserted into SQLite without catching parsing (`json.JSONDecodeError`) or database execution (`sqlite3.Error`) exceptions. A malformed payload or database failure would cause Flask to return a 500 status along with a stack trace or overly verbose error output depending on the environment, potentially exposing sensitive application logic and database schema details.
**Learning:** External webhook boundaries must anticipate malformed input and infrastructure errors. The fail-open behavior in exception handling directly contradicts the "Fail securely" philosophy.
**Prevention:** Always wrap parsing and state mutations in `try-except` blocks on externally-facing endpoints, specifically returning generic error responses (e.g., generic 400 or 500 error messages) and securely logging the failure internally, instead of allowing unhandled exceptions to propagate to the caller.
