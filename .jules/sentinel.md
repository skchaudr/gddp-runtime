## 2024-06-04 - [Fix fail-open signature bypass]
**Vulnerability:** The webhook signature validation in `scripts/intake_server.py` had a fail-open configuration. If `WEBHOOK_SECRET` was missing, it returned `True` bypassing signature checks. Also, the `/webhook` route had `if WEBHOOK_SECRET and not verify_signature(payload_bytes, sig):` which skipped validation if no secret was configured. Unhandled exceptions during JSON loading or SQLite queries could potentially leak stack traces or cause unpredictable application state.
**Learning:** Security controls like signature verification should be fail-closed. If the expected configuration for validation is missing, validation should fail instead of bypass. Error states during data processing (e.g., malformed payloads, database connection failures) should be explicitly caught and handled to prevent information leakage (e.g., returning 400 or 500 status codes without exposing internal tracebacks).
**Prevention:** Always default to "deny" (return False) when validation configuration is missing. Remove bypass conditions from route handlers. Explicitly catch anticipated exceptions (like `json.JSONDecodeError` and `sqlite3.Error`) to prevent internal exceptions from propagating to the client.
