## 2025-02-28 - [CRITICAL] Fail-Open Webhook Authentication Fixed
**Vulnerability:** The `verify_signature` logic in `intake_server.py` had a "fail-open" vulnerability where it returned `True` (bypassing authentication) when the `WEBHOOK_SECRET` environment variable was missing or unconfigured. Additionally, the `/webhook` route was structured to only perform validation if `WEBHOOK_SECRET` evaluated as truthy, making the signature check optional by default. Stack traces were also leaked from payload parsing exceptions, such as `JSONDecodeError` or `sqlite3.Error`.
**Learning:** Returning `True` (default-allow) on missing security configurations completely breaks the security barrier, enabling attackers to spoof webhook payloads, leading to potential RCE or system takeovers depending on event-handling logic. Stack traces from exceptions reveal server internals, providing attackers an avenue for discovery.
**Prevention:** Always "fail securely" by denying access (e.g., returning `False` or returning generic errors like 400 or 500) when configurations are missing or runtime operations fail. Default to enforcing strict validation checks in routes without relying on environment variable presence bypasses.
