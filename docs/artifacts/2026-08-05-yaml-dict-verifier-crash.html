Postmortem · Production Incident

Unquoted YAML scalar parsed as a dict and crashed the deterministic verifier

A constraint written as - Read-only: inspect and report only… was parsed by YAML as a single-key mapping, not a string. The authoring validator flagged it only as a non-blocking warning; the value sailed through to the runtime, where it crashed the first evaluation tick of an autonomous loop.

02 / What the author intended vs what YAML produced

A colon in a list item is not a string — it is a mapping

Step through the parse. The author meant one string. YAML's inline Key: value rule produces a one-key dict. The downstream code assumed every list item was a string.

graphs/vm-harness-audit/nodes/node-03-subagents-chains-audit.yaml
# the broken line — unquoted, leading "Read-only:" constraints: # broken ↓ - Read-only: inspect and report only; do not modify chain configs # fixed (after e68ed45) ↓ - "Read-only: inspect and report only; do not modify chain configs"
Quoting the scalar makes YAML treat the whole line as one string. Without quotes, the Key: prefix triggers a block mapping. Four constraints across four nodes had this shape before commit e68ed45.
What the author intended — a string
str = "Read-only: inspect and report only; do not modify chain configs"
A single list element of type str. Every downstream consumer — path extraction, dedupe, pattern scan — is written for this type.
What YAML produced — a dict
dict = {'Read-only': 'inspect and report only; do not modify chain configs'}
A one-key mapping. Not hashable-compatible with the string APIs below it. The value reaches mentioned_paths_from_text(), which calls re.findall(pattern, text) on a dict and raises TypeError: expected string or bytes-like object.
Why this is easy to miss The line reads as perfectly natural English. The defect is invisible to the eye and only surfaces to the YAML loader — and to whatever code first assumes the item is a string.
03 / The detonation point and the tolerance fix

The crash was an unguarded string operation, not a dedupe

The list of constraint strings was iterated directly into path-extraction. The fix did not convert dicts to strings — it guarded the type, warned loudly, and skipped.

before · crashing @ 185e6fe^ 
 for text in node_yaml.get("constraints", []):
     # text may be a dict, not a str
     files.update(           # no type guard
         existing_paths_from_text(repo, text)
     )
 
 # existing_paths_from_text → mentioned_paths_from_text
 #   re.findall(pattern, text)
 #   text is a dict  →  TypeError
 >>> TypeError: expected string or
     bytes-like object, got 'dict'
after · tolerant @ 185e6fe 
 for item in node_yaml.get("constraints", []):   # renamed text → item
+    text = item.get("constraint", "") if isinstance(item, dict) else item
+    if not isinstance(text, str) or (isinstance(item, dict) and not text):
+        print(f"[constraints] non-string constraint "
+              f"in node {node_id!r}; skipped — "
+              "quote YAML scalars containing ':'", file=sys.stderr)
+        continue
     files.update(
         existing_paths_from_text(repo, text)
     )
 # warn + skip, never crash the tick
The same guard was applied to criteria An identical isinstance(criterion, str) guard protects the acceptance_criteria path in the same function, so a mapping-shaped criterion is skipped with the same author-facing message rather than reaching mentioned_paths_from_text().

05 / The lesson

The same error costs more the later it is caught

Detection has a price that compounds by layer. A defect caught at author time costs a message; the same defect caught at run time costs a crashed tick in a loop with no human watching. The fix moved detection as far left as it could.

Author
cheap
~0 s
Quote the scalar. The defect never exists.
Validate
low
seconds
A blocking error at validate. Fix before commit.
Deploy
medium
minutes
Caught on sync only if a pre-flight inspects types.
Evaluate
expensive
~25 min
A dead tick in a live autonomous loop. No verdict, no evidence, a stuck frontier.

Commit 185e6fe made the evaluator tolerant so a future authoring slip can never again kill a tick. The remaining move is to make the validator block it — turning the existing warning into a rejection at the layer where the defect is cheapest to fix.

07 / Methodology

Every claim was checked against source

This postmortem corrects four inaccuracies present in the briefing. Each fix is anchored to a commit or file line. Accuracy over narrative.

Corrections to the original incident brief

  1. Broken scalar text. Brief said - Key: PRESERVE...; the real broken text was - Read-only: inspect and report only... across 4 nodes.
    gddp-config · e68ed45 · node-01..04 YAML
  2. Crash mechanism. Brief described a item not in seen set-dedupe raising TypeError: unhashable type: 'dict'. That code does not exist. The real crash was re.findall() inside mentioned_paths_from_text() receiving a dict and raising TypeError: expected string or bytes-like object.
    gddp-runtime · 185e6fe (message) · probes.py:471 · verified by reproducing in python3

  4. Validator silence. Brief said the validator "never checked" for non-string items. The check already existed and flagged this exact pattern — but as a non-blocking warning (exit 0 without --strict), so the file passed. The open follow-up is therefore to promote the warning, not add one.
    gddp-config · scripts/validate.py · ~L181 (criterion str check) + ~L185–199 (implicit_mapping_in_list warning), present at e68ed45
