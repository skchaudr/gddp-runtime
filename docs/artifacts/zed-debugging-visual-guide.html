A first successful Python debug in Zed

Interactive simulator of the five-minute exercise in this repo. Pair with the Markdown guide. Numbered steps load a complete debugger snapshot. F-keys work when this page is focused.

profile GDDP: five-minute debugger tour breakpoint retry_budget.py:96 documented = action / F-key / panel name inferred = icon, color, picker layout, adapter stop line

Plain fallback (readable without the simulator)
  1. Select .venv at the right of the status bar (toolchain: select). Expected: that name stays in the status bar.
  2. Open the test file to see the trigger. The tour profile does not use $ZED_RELATIVE_FILE.
  3. Open retry_budget.py.
  4. F9 / gutter on line 96.
  5. F4 → GDDP: five-minute debugger tour. GDDP: current pytest file runs the whole active file.
  6. Paused at 96 in should_retry. Locals: verdict="needs-human-review", summary src/foo.py has a bug, attempt=0, retry_budget=2, criteria_findings=None. has_evidence unavailable until the line runs.
  7. Console: Enter evaluates; Alt-Enter adds a watch to Variables.
  8. Step Over: stay in should_retry, has_evidence=True, line 97.
  9. Cmd/Ctrl-Shift-F5 restart → line 96 again. Shift-F5 alone stops.
  10. Step Into: expected executable stop is line 30 (adapter-inferred). Line 23 is the declaration only. Caller watches are unavailable until you select the should_retry frame.
  11. Stop, F9 to clear. Empty last-failed cache: pytest exits status 5 (no tests collected), not a debugger failure.
