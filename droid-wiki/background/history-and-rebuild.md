## What “rebuild” meant

The rebuild was not a rewrite. It challenged foundations that had grown from unverified assumptions:

- Human ownership of completion had been interpreted as “every dependency waits for a human.” Provisional flow restored unattended sequencing without granting acceptance authority.
- Base-integrity checks rejected returned work before an evaluator could judge it. The revised rule makes base state evidence or merge admission, not a silencer.
- A missing Jules automation setting led to patch extraction, base binding, spools, and guards. The rebuild used this as the canonical example of a workaround becoming architecture.
- GitHub webhook intake had been treated as the front door even after direct operator and executor paths existed.
- The old decision loop and live heartbeat embodied parallel notions of dispatchability.

The standing measure became: does a mechanism help put a trustworthy intent/integrity judgment in front of a human while preserving forward motion?

## Reckoning status

The July 31 reckoning was a worksheet, not doctrine. It found an aligned live spine—node, direct dispatch, durable attempt state, evaluator, provisional gate, base-chaining, and human review—surrounded by inherited GitHub ceremony, duplicated policy, an older decision loop, and stale adapter assumptions.

Those classifications are historical evidence, not permanent deletion orders. Current code may have advanced since the worksheet. Verify live behavior before acting.

## Provisional decisions

“Provisional” has two meanings that must not be mixed:

- A graph node status: evaluator-backed execution eligibility pending human acceptance.
- Historical design text: a proposal or ruling at a point in time.

`/Users/sab-mini/repos/gddp-runtime/docs/GDDP-rebuild.md` records an explicit operator decision on 2026-07-29: provisional is default, has no confidence floor or chain-depth limit, and `human_gate` is the opt-in brake. Later canonical documents still control if prose conflicts.
