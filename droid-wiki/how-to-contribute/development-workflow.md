# Development workflow

Branching, commits, handoffs, and the definition of done for `gddp-runtime`. Written for Saboor and any agent working in this repo.

## Branching

- Work branches off `main` (the repo default). Example: `feat/khoj-idle-shutdown`, `fix/mission-push-guard`.
- Prefix suggestions: `feat/`, `fix/`, `docs/`, `chore/`. The prefix is advisory; the reviewer cares about what the diff does, not the prefix.
- Do not create parallel branches for the same task without a reason recorded in the handoff. Check `git branch -a` before starting.
- If work continues from another branch, first understand whether it should be merged, rebased, abandoned, or left as a PR branch.

## Before any work

1. `git status --short --branch` — if dirty, stop and classify the existing state. Do not silently overwrite inherited changes.
2. On any armed control plane (`sab-mini`, `pi-big`, etc.), run `git pull --ff-only` first. Repo files on production change only via git.
3. Verify branch: `git branch --show-current`. Upstream: `git rev-parse --abbrev-ref --symbolic-full-name @{u}`.
4. `git fetch --prune` before merge/rebase decisions.

## Small commits

Co-author ALL Git commits with `<agent-name> + <model>` (e.g., `Co-authored-by: droid + gpt-5`). Traceability is non-negotiable.

Commit at coherent checkpoints, not when the diff is pretty. A repo with hours of uncommitted agent work is an unsafe handoff state. Prefer small commits over large commits. The message should say what changed and why the next reader needs to know.

Example style:

```
fix(mission): detect early process exits and surface stderr on failure

When the worker exits before writing exit.json the mission adapter
treated it as "running" forever. Read stderr and surface the real
failure reason so the reconciler can route to awaiting_review with
evidence instead of polling until timeout.

Co-authored-by: droid + gpt-5
```

## PR and merge expectations

This is a mostly-solo repo. PRs are lightweight: a branch pushed and (when helpful) a PR opened on GitHub so diffs can be reviewed externally. There is no mandatory reviewer, but Saboor reviews before merging to `main`. Agents must not merge their own branches without explicit approval.

If you open a PR:

- Target `main` unless told otherwise.
- Describe what the branch adds relative to the base, not just the latest commit.
- Keep the PR description self-contained: what changed, what it does not change, residual risk.
- Do not force-push shared branches without authorization.

## Definition of done (AGENTS.md end-of-session contract)

Session is not done until all of these are true:

1. Ran the relevant validation/build/test commands and recorded the results.
2. `git status --short --branch` is clean and synced with upstream. Anything left over must have a path and reason.
3. All intended changes are committed. No staged, unstaged, or untracked task artifacts for the next session to interpret.
4. The working branch is pushed. If the task is meant to land on `main`, it is merged to `main`, pushed, and local `main` matches `origin/main`.
5. A handoff is left in `.handoffs/` covering branch, commit, pushed status, validation, changed surfaces, and residual risk.

Not-done triggers (do not report completion if any of these hold):

- Uncommitted task changes remain.
- Local commits are not pushed.
- Branch is diverged and unresolved.
- Merge conflicts or stash entries remain.
- Validation failed with no explicit follow-up decision.
- Generated files, logs, caches, or media are untracked and unclassified.

## Handoff discipline

The `.handoffs/` folder is the bridge between sessions. Use it at every natural checkpoint after the initial task is complete.

- Template: `.handoffs/000-template.md` (never overwrite the template with session notes).
- Next number: `.handoffs/<NNN>-<short-description>.md`. The counter currently runs past 083.
- Fill only the `Agent Section`. Do not write below `Do NOT edit this file past this point`.
- Keep it short and empirical: date, branch, touched files, git state, artifacts, exact resume point.
- Required before claiming completion if the repo had merges, branch changes, conflicts, generated artifacts, failing validation, or state the next agent would otherwise rediscover.

## Production host rules

On `sab-mini` (the production control plane) and any armed host:

- `git pull --ff-only` is step zero.
- Repo files change only via git — never `scp`, never remote edits.
- Session is not done until `git status --porcelain` is empty and HEAD matches `origin/main`.
- Do not run the heartbeat runner directly. Use [`deploy/mini-heartbeat/bin/`](../../deploy/mini-heartbeat/bin/) (`arm.sh`, `smoke.sh`, `disarm.sh`). See [Tooling](tooling.md).

## Agent-specific rules

- Agents never author nodes into the live graph. Retry is same node, same scope. Out-of-scope discoveries become a continuation proposal for the human.
- Retry-triggering evaluator findings must cite a concrete repo path (optionally `:line`), graph node id, or canonical document. Vague findings go to human review, never to work.
- Evaluator context deliberately excludes `AGENTS.md` (executor-facing). Integrity/criteria lanes read README, project brief, foundational node, and DAG neighbors.
